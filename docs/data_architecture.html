Companion to the Architecture Register · 3dwag98/afa

The data layer, rebuilt

Where every required input actually comes from, how to store it so look-ahead is structurally impossible, and eleven places where the platform's current model of the Indian market is wrong rather than merely incomplete.

Start hereThe finding that reorders everything else

The platform keys everything on the trading symbol. In Indian equities the symbol is not stable — companies rename, and the exchange reissues the ticker. ISIN is the identifier that persists.

This is not a detail to tidy up later. Keying on symbol means a rename appears in your data as a delisting plus a new listing: the old series ends, a new one begins with no history, and every lookback feature on that name silently restarts. Cross-sectional rankings then compare a name with 250 days of history against one that appears to have 12. The eod2 project — a working local NSE store — handles this explicitly, tracking ISIN through symbol changes.[8]

Every schema below is keyed on ISIN with symbol demoted to a time-ranged attribute. Fixing this after the store is populated means rebuilding it.

Two pieces of guidance that are now stale

The CSV bhavcopy is gone. NSE discontinued cm<DD><MON><YYYY>bhav.csv.zip on 8 July 2024 (circular 62424, 12 June 2024). The replacement is UDiFF — a SEBI-mandated Unified Distilled File Format covering cash, F&O, currency, EGR and commodities.[1][2] Any ingestion code or tutorial predating mid-2024 targets a dead URL.

The obvious index-membership file is abandoned. archives.nseindia.com/content/indices/IndexInclExcl.xls stops at 31 July 2020.[4] Building point-in-time membership from it gives you five stale years and no warning.

Access reality

NSE endpoints require a browser-like session — cookies obtained from a homepage visit, correct headers, and rate limiting — and they break periodically. Do not write this from scratch: jugaad-data and nselib both target the current NSE site and handle session and caching, and jugaad-data explicitly warns that libraries built on the old site are dead.[3] eod2[8] is worth reading before designing anything, since it already solves the ISIN-tracking and adjustment problems locally.

Keep the HuggingFace dataset

vishnun0027/indian-market-historical-ohlcv is versioned and pinnable — properties NSE scraping does not have. Use it as the reproducible baseline for price history and layer the NSE-sourced facts on top. Two sources that agree are also the cheapest data-quality check available.

Part 2 · StorageHow to store it so leakage is structurally impossible

One rule drives the whole design: every fact carries two dates — the date it describes, and the date it became knowable. Any query is then "as of" a point in time, and a leak requires actively passing the wrong argument rather than merely forgetting something.

A quarterly result published on 15 May describing the quarter to 31 March must be invisible to a query dated 14 May. Without knowledge_date, that class of leak is undetectable by inspection — the data looks completely normal — and it inflates precisely the factors people most want to add.

Engine: DuckDB over parquet

Given no local ingestion constraints, this is the right shape for a single-machine research platform: columnar parquet on disk as the durable format, DuckDB as the query engine over it. Real SQL with window functions and as-of joins, no server to run, no separate storage format, and the parquet files stay readable by pandas and by anything else you point at them. A client–server database earns its keep with concurrent writers; a research store has one.

The three columns that do the work

ColumnMeaningWhat it prevents
isinStable security identityA rename appearing as delisting + new listing, restarting every lookback feature
effective_dateThe date the fact describes—
knowledge_dateThe date the fact became knowableLook-ahead on anything published later than it describes: results, restatements, index changes, surveillance actions

Reference tables use half-open intervals [valid_from, valid_to) with valid_to = NULL for current. Membership then becomes a join rather than a filter, and "what was in the NIFTY 50 on 2021-03-15" is a query rather than an assumption.

The access rule

One function, and nothing bypasses it:

panel = store.as_of(
    date="2023-06-30",        # nothing with knowledge_date > this is visible
    universe="NIFTY500",      # resolved from index_membership at that date
    fields=["close_adj", "deliv_per", "sector"],
)

Enforce it in one place and leakage stops being a discipline every strategy author must maintain. This also makes the conformance test from the architecture review trivial to write: request a panel as of date t, assert no returned row carries a knowledge_date after t.

Scale

Roughly 2,400 symbols × ~250 sessions × 30 years is on the order of 18 million rows — a few gigabytes of parquet. F&O with full option chains is the only part that gets genuinely large, and it partitions cleanly by year and expiry. This is a laptop-scale problem; do not over-engineer it.

Part 3 · CorrectnessIs the model right for Indian markets?

Eleven checks against how the market actually works. Four are wrong today in ways that produce plausible, incorrect numbers; five are missing; two the platform already gets right and should keep.

Symbol as the primary key Wrong

Symbols are reissued after renames. Keying on them fragments history at exactly the names that had a corporate event — which is a biased subset, not a random one. ISIN is stable and every exchange file carries it.

Only adjusted prices are kept Wrong

The ingestion back-adjusts OHLC by adj_close/close and discards the raw prices. That is correct for computing returns and wrong for everything band-related: a circuit limit applies to the actual traded price, so a circuit check run against a back-adjusted series is comparing the wrong number to the band. Store both.

Series is not modelled at all Wrong

NSE series matters enormously and appears nowhere. EQ permits intraday netting; BE and BZ are trade-to-trade — every trade settles by compulsory delivery, so an intraday exit is not merely expensive but impossible. Surveillance moves names into T2T.[6] A backtest that assumes it can exit a BE position the same day is simulating a trade the exchange would not permit.

Circuit limits are inferred from price behaviour Wrong

The platform detects circuit locks by looking for suspicious price action. The bands are published daily per security and change — including as a surveillance consequence. Inference produces both false positives (a genuine 20% move on an unbanded stock) and false negatives (a 5% band the code never considered).

Delivery percentage Missing

Free, daily, in the file already being downloaded, and one of the few genuinely India-specific signals available. High price move on low delivery is churn; the same move on high delivery is accumulation.

F&O ban periods Missing

A stock in ban permits no fresh derivative positions.[5] Two uses: as a tradability constraint, and as a crowding indicator — entering ban means positioning has reached 95% of the market-wide limit.

ASM / GSM / ESM surveillance state Missing

Surveillance brings tighter bands, T2T settlement, 100% margin and periodic call auctions.[6] A name under ESM is barely tradeable at size. This is a hard exclusion filter the platform does not have, and SEBI's framework was re-consolidated as recently as the May 2026 master circular.[6]

Free-float vs total market cap Missing

Indian indices weight by free float, and promoter holdings are frequently 50–75%. Any size factor or capacity estimate built on total market cap is wrong by a large and name-specific multiple.

Settlement cycle and expiry effects Missing

India moved to T+1 in January 2023 and runs an optional T+0 for a growing list of scrips.[6] A backtest spanning the transition uses one settlement assumption across a boundary where it changed. Separately, weekly index-option expiries produce systematic patterns a daily model will absorb as noise.

Back-adjustment by adj_close/close, all four legs together Correct

Scaling open, high, low and close by the same per-row factor preserves intraday relationships — a locked session with high == low stays locked, and ATR keeps its proportion to price. Leaving volume unadjusted is also right for a 60-day liquidity screen. This part is well done and the reasoning is written down where the code is.

Pinning a versioned dataset revision Correct

hf_revision makes a run byte-reproducible. Extend the same idea to NSE-sourced data by storing the raw downloaded file alongside the parsed table — re-deriving beats re-downloading when a parser turns out to be wrong.

Part 4 · SequenceBuild order

Week 1

The spine

security, symbol_history, calendar. Backfill ISINs onto the existing parquet cache and confirm how many names have had a symbol change — that number is the size of the problem you have been carrying silently.

Week 2

Point-in-time membership

Monthly constituent snapshots from niftyindices, converted to [from, to) intervals. This is the one that changes what your backtests mean. Re-run one existing backtest before and after; the difference is the survivorship bias you have been reporting as edge.

Week 3

Daily facts

UDiFF bhavcopy and sec_bhavdata_full: raw and adjusted OHLCV, delivery, series, price band. Sector map from sector-index membership, which turns the dormant concentration cap back on.

Week 4

Events and the as-of gate

Corporate actions, surveillance state, F&O ban, flows — all with knowledge dates. Then store.as_of() as the only read path, and the leakage conformance test that asserts it.

Later

Fundamentals, intraday, F&O chains

Once the bitemporal store exists to hold them honestly. Start accumulating intraday bars early even if unused — broker history is capped at 60–90 days, so it can only be gathered forward.

The one measurement that justifies the whole exercise

After week 2, re-run an existing cross-sectional backtest against point-in-time membership and put the two equity curves side by side. That single chart converts D9 from a caveat everyone nods at into a number, and it is the most useful thing this entire data effort will produce.
